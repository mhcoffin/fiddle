# Unpitched percussion bridge

A bridge for Dorico's unpitched instruments: an expression map and a
**percussion map** (Dorico's instrument + techniques → pitch table) in one
library, so Fiddle receives every stroke, roll and dynamic as Dorico plays
it. Plan: `/Users/mhc/.claude/plans/zany-sprouting-perlis.md` (2026-10-30).

Status: **the probe has not been played in Dorico yet.** `unpitched-percussion-r1/`
is a candidate built on the "both maps see every technique" assumption; it is
regenerated once `results-01.md` exists.

## How it works

Dorico plays an unpitched note by looking its techniques up in the endpoint's
percussion map, which gives the MIDI pitch (and optionally a keyswitch), while
the endpoint's expression map still chooses a base switch (CC102) and add-on
switches, and fixes where the dynamic goes (velocity or CC1). This bridge
uses both:

- **Strokes are pitch codes.** The percussion map gives every covered
  instrument the same table (`profiles.py`, `CODES`): Natural 36, the strokes
  and surfaces 37–68 (centre, edges, rim, rim shot, side stick, bell, …), the
  roll family 72–81 (roll, tremolo, buzz, press, flat, circular, swoosh rolls,
  trills), openness 84–87 (closed, half-open, open, pedal). The chair names
  the instrument; the pitch names the stroke. 21–35 and 90–114 are reserved
  (drum-set kits; stroke × modifier combinations if Dorico needs them).
- **Modifiers are add-ons** on the pitched-percussion conduits: accent and
  marcato CC104, beaters CC105, dead stroke CC108, muffled CC109, the dynamic
  marks CC118/119 and KS0, ghost note KS4, damp KS12, l.v. KS13, plus snares
  on/off CC112, throw-off CC113 and choke CC114 (conduits no pitched
  dimension uses).
- **Dynamics:** the hit bases (natural, staccatissimo, staccato, staccato +
  tenuto, tenuto, codes 0–24) take velocity; every roll kind is also a base
  (codes 25–74) with CC1 dynamics, so a hairpin rides a roll. Playback
  options are pinned as in the other r2+ maps (written durations, no
  same-pitch truncation, 10-tick switch lead, linear dynamics −8..8, no
  articulation deltas). Dorico's *unpitched* humanize and beat-stress
  options stay project settings (set them to 0 for tests, as for pitched).

Generated by the shared engine (`../orchestral-strings-bridge/generate.py`,
which gained `spec.BASES` for per-base dynamics and `spec.PERCUSSION` for the
percussion map) from `profiles.py`:

    python3 experiments/unpitched-percussion-bridge/generate_unpitched.py   # --check to verify
    python3 -m unittest discover experiments/unpitched-percussion-bridge

## Phase 0: what only Dorico can tell us

| | Unknown | Why it matters |
| --- | --- | --- |
| U0 | Does Dorico import one `.doricolib` holding both an expression map and percussion maps? | One file per section keeps Fiddle's pins, hashes and installer unchanged. |
| U1 | When the percussion map resolves a technique, does the expression map also switch on it? | Decides whether rolls can take CC1 dynamics through a base row, and whether accents etc. arrive as add-ons. |
| U2 | Is a roll one sustained note at the roll's pitch with CC1 following the hairpin, or repeated strokes? And without an entry? | Whether the roll family needs entries, and how Fiddle will render rolls. |
| U3 | For a two-technique note, which entry wins: the exact combination, the best subset, or Natural? What does a technique with no entry become? | Whether r1 needs combination codes (reserved 90–114), and whether every offered technique needs an entry. |
| U4 | What does an entry's own `<keyswitches>` field send? | A possible second conduit for r2. |
| U5 | Do direction techniques (beaters, snares on/off) reach the expression map, the pitch, both or neither? | Whether they stay add-ons or need combination codes. |
| U6 | Is velocity on the pinned linear curve exactly `round(1 + 126·(level+8)/16)` (ppp 40 … fff 88)? Any beat stress? Is CC1 also sent on hits? | Whether hits can keep velocity dynamics. |

### The probe

`probe/Fiddle-Orchestral-UnpitchedProbe-r1.doricolib` holds the probe
expression map (`xmap.user.Fiddle.UnpitchedProbe.r1`: Natural by velocity;
roll, tremolo and buzz roll bases on CC1; add-ons accent/marcato CC104,
beaters CC105, strike location CC106 with **rim deliberately also a pitch
code**, dead stroke CC108 **deliberately not a pitch code**, ghost KS4, damp
KS12, snares CC112) and two percussion maps for the snare drum:

| Map A `…UnpitchedProbe.A` | pitch | Map B `…UnpitchedProbe.B` | pitch |
| --- | --- | --- | --- |
| Natural | 60 | Natural | 60 |
| Rim | 61 | | |
| Side stick | 62 | | |
| Cross stick | 63 | | |
| Roll | 64 | | |
| Tremolo | 65 | | |
| Buzz roll | 66 | | |
| Rim + Roll | 67 | | |
| Rods (beater), keyswitch 15 | 68 | | |
| Rods + Rim | 69 | | |
| Accent | 70 (diagnostic) | | |

`unpitched-probe.musicxml` (`make_probe_score.py`) has two snare drums at
♩ = 100, 4/4. Part A plays through map A, part B through map B:

| Bar | Part A | Answers |
| --- | --- | --- |
| 1–2 | one hit per beat, ppp pp p mp / mf f ff fff | U6 |
| 3 | eight mf eighths | U6 beat stress |
| 4 | accent, marcato, ghost note (parenthesized head), plain | U1 |
| 5 | whole-note roll under p < f | U2, U1 (roll base) |
| 6 | buzz roll (half), roll marked **rim** (half) | U3 |
| 7 | **rim**, **side stick**, x notehead, **dead stroke** | U3 (import of x head; no entry for dead stroke) |
| 8 | **Rods**, four hits | U4, U5 |
| 9 | four hits marked **rim** | U5 combination |
| 10–11 | **Snares off**, four hits; **Snares on**, four hits | U5 |
| Part B, 5–6 | the same rolls | U2 without an entry |

Bold marks are not in the MusicXML: add them in Dorico (Shift-P popover
text in parentheses): bar 6 beat 3 `rim`; bar 7 `rim`, `side stick`,
`dead stroke` (beat 4); bar 8 beat 1 `Rods`; bar 9 `rim` on each hit; bar 10
`Snares off`; bar 11 `Snares on`. If the import dropped the buzz roll (bar 6
beat 1, "z" through the stem) or the ghost note (bar 4 beat 3), add those
too. Save the project as `Unpitched probe.dorico` here.

### Dorico setup and capture

1. With Dorico closed, copy the probe `.doricolib` to where Fiddle installs
   its bridge maps, then start Dorico:

       cp experiments/unpitched-percussion-bridge/probe/Fiddle-Orchestral-UnpitchedProbe-r1.doricolib \
          "$HOME/Library/Application Support/Steinberg/Dorico 6/DefaultLibraryAdditions/Fiddle-Probe-UnpitchedPercussion-r1.doricolib"

   **U0:** Library ▸ Expression Maps should list "Fiddle Bridge - Unpitched
   Percussion Probe r1" and Library ▸ Percussion Maps both "Fiddle Unpitched
   Probe A/B". (Library ▸ Import Library… can't answer this: each of its
   two entry points imports only its own kind of entity from the file, so an
   import as an expression map drops the percussion maps and vice versa.
   Fiddle never imports; it installs files here.)
2. Open the MusicXML. Both parts should come in as Snare Drum; add the bold
   marks above.
3. Play ▸ Endpoint Setup for the Fiddle MIDI Probe instance: part A on
   channel 1 with expression map "Fiddle Bridge - Unpitched Percussion Probe
   r1" and percussion map "Fiddle Unpitched Probe A"; part B on channel 2 with
   the same expression map and map B. Note whether Dorico offers map A for a
   single snare (`forSingleInstrument` is true); if not, say so in the
   results and we regenerate it false.
4. Playback Options: humanize (unpitched) 0, beat stress (unpitched) 0.
5. Play from the start past bar 11. Quit Dorico so the probe closes its
   capture, then:

       python3 experiments/unpitched-percussion-bridge/check_probe.py "$TMPDIR"/fiddle-midi-probe-*/capture.jsonl

   `--extract events.json` saves the pass for a fixture. Record the
   verdicts and U0 in `results-01.md`.

`test_check_probe.py` plays the score through a small Dorico simulator under
each hypothesis, so every verdict is exercised before a capture exists.
